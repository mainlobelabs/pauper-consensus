# Gotchas

Hard-won constraints discovered during harness runs. Workers MUST read these before touching code; the orchestrator appends here the moment a landmine is found so it never has to be re-typed into the next worker prompt.

- [design] Dataset spike (zero API cost): PrOntoQA as bundled in ProverGen is UNSUITABLE as the sole formal stratum — 500 items, explanation chains ALL exactly length 11, and 0/500 contain a conjunctive rule. Every inference is single-premise modus ponens, so it cannot exercise protocol invariant 7 or E2.5 multi-premise dependency evaluation, and the uniform depth gives no variation for the complexity prior. ProofWriter has the right structure (574/600 items carry conjunctive rules) but the ProverGen bundle strips the proof field; the ORIGINAL Allen AI ProofWriter release is required for proof trees. ProverQA must be downloaded separately from HuggingFace and is untested.
- [design] RESOLVED (2026-08-07): the formal stratum is `hitachi-nlp/proofwriter_processed_OWA` on HuggingFace, which is the ProofWriter OWA release WITH proof trees intact — the field the ProverGen bundle strips. Measured on `depth-3/test` (1,405 items): 95.5% of items carry at least one conjunctive rule, 43.0% of all 9,436 rules are conjunctive, QDep spans 0-6 and proof length spans 1-9. This exercises protocol invariant 7 and gives E2.5 real multi-premise dependency ground truth, both of which PrOntoQA could not. The True/False/Unknown answer split (5,620/5,620/9,106) maps directly onto the three-state affirm/deny/silent observation model of D9. Downloadable without an HF token. ProverQA is no longer needed.
- [env] The resource table in EXPERIMENT.md 0.3 is STALE as of 2026-08-07 and must be re-measured at R0 rather than read. Host RAM is 247 GB total / 225 GB available, not "~21 GB"; local generation now WORKS for 3 distinct families. Conclusions drawn from the old table — in particular "the binding constraint is authenticated request quota, not local compute" — no longer follow automatically.
- [env] Local `:1234` panel, smoke-tested 2026-08-07: `thinkingcap-qwen3.6-27b`, `laguna-xs-2.1`, `ornith-1.0-35b` and `ornith-1.0-35b-mtp-apex` all load and generate; `deepseek-v4-flash` FAILS to load ("Error loading model"). That is 3 distinct families, not 5, and ornith-35b/ornith-35b-mtp-apex are two variants of one family so they must not be counted as independent sources. Reasoning models return their trace in `reasoning_content` with `content` EMPTY when the generation is cut off mid-thought — a small `max_tokens` silently yields empty answers rather than short ones.
- [env] The local `:1234` server serves ONE model at a time. Three concurrent requests to three different models returned http 400 and 500 for two of them while only the third succeeded; it evidently JIT-loads and evicts. Generation must therefore be sequential, and the runner must be MODEL-MAJOR (all items for one model, then the next) so each model is loaded once instead of thrashing on every item. Do not add a thread pool: it will look like a flaky endpoint.
- [env] The single-model-slot constraint also hits the EMBEDDING endpoint: `/v1/embeddings` intermittently returns http 400 while a generation run is in flight, because the server is swapping the generation model in and out of its one slot. The same request succeeds on retry. Treat a 400 here as contention, not malformed input — `measure.embed` retries with backoff. NLI is unaffected: it runs in-process via transformers, not through `:1234`.
- [toolchain] codex writes a models_cache.json (~/.codex/models_cache.json) it then fails to deserialise: 'missing field supports_reasoning_summaries at line 88 column 5'. This kills EVERY tier in the worker cascade in ~25s with rc=1 and no diff, which looks like tier exhaustion but is a purely local tooling fault. Check codex.stderr before concluding the free tier is exhausted.
- [harness] Do NOT run embedding or analysis calls against `:1234` while a generation run is in flight. The single-model-slot contention does not merely fail the ANALYSIS request (which retries); it also knocks out concurrent GENERATION requests with http 400. Four generations were lost this way during the E0/E1 run. Analysis is cache-only by design, so simply wait for generation to finish.
- [harness] `nodes.Client.generate` must NOT cache failed generations. The artifact cache is write-once, so persisting an error freezes a transient fault in permanently — a 400 from momentary model-swap contention becomes the model's recorded "answer" and no later re-run can repair it, because the re-run is a cache hit. Only successful artifacts are immutable. Errored keys already written must be deleted before re-running.
- [instrument] Negative-polarity canonical propositions are NEVER scored: 0/607 across both panels' E1 runs (measured 2026-08-15 over the frozen cache). The alignment layer only ever lands claims on positive-polarity propositions, so every scorable negative is a positive-polarity FALSEHOOD (46 in the current corpus, of which ~62% score). Corpus enrichment for negatives must therefore target pos-pol y=0 counts, not raw y=0 counts, and any "prevalence" argument about the proposition set must be made over the scorable subset.
- [instrument] The ornith family formats derivations as "Step N: ... derive ..." which collides with the "step " prefix in extract.py's _NOISE filter: 46.2% of derivation-cue segments corpus-wide never become claims (52.6% on the local panel; ornith 53-57%), and 1,299/1,704 step-prefixed fixable segments are ornith-family. A surgical exemption — admit _NOISE-rejected segments that begin "step " and carry a derive cue — sampled at 20/20 genuine claims; a blanket _NOISE relaxation sampled at 50% noise. Applying it requires re-running alignment: new LOCAL embedding calls (zero API quota) plus NLI compute, so it is an attended-run change, never a hot fix mid-analysis.
- [instrument] Model-written "rule N" references do NOT reliably follow theory order: agreement with content-matched rule identity is 0.52 (laguna) to 0.84 (nemotron), below any usable bar. Anything that parses rule citations must match by CONTENT against item.rules; numeric refs are corroboration at best. (Ground-truth proof strings are the opposite: ruleN = item.rules[N-1] verified 900/900.)
- [design] measure.embed caches on a hash of the WHOLE text list (wct/measure.py:_h), so alignment cannot be re-run on a different or reordered claim/target list without a total cache miss -- which then hits the :1234 embedding endpoint and would silently re-embed ~2GB. Any corrected alignment path MUST issue byte-identical measure.embed calls to cluster.align_anchored (same text lists, same order) and change only what it RETAINS after NLI. Run every cache-only re-analysis with WCT_LOCAL_BASE pointed at an unroutable address (e.g. http://127.0.0.1:9) so a cache miss fails loudly instead of quietly generating.
- [design] out/cache/embed and out/cache/nli are gitignored, so a detached worktree does NOT have them; only out/cache/generation (2176 files) and data/*.parquet are tracked. Any worker check that touches the real cache must set WCT_CACHE=/home/jmannings/dev/waveconv/out/cache and use the live venv at /home/jmannings/dev/waveconv/.venv/bin/python with PYTHONPATH=$PWD, or it will try to rebuild 2GB of embeddings.
- [toolchain] Worker sandboxes have NO PyPI egress and bare 'python' is system 3.14 with none of the project deps (httpx/torch/transformers/numpy), so 'import wct.measure' fails and pytest collects 0 items. compile-tasks does NOT inject relay.py runner's pinned command into task.md, so every task's own text must state it: run everything with /home/jmannings/dev/waveconv/.venv/bin/python (3.12) and never pip install or create a venv. A worker that is not told this burns its entire budget on externally-managed-environment and connection errors and gets rejected with a complete, unverified diff.
- [design] wct/cluster.align_anchored has NO extension point for the pre-collapse (claim, target) assignments: it returns only the per-(agent,pid) argmax, and the intermediates (ci, ti) are local. You CANNOT recover them by recording its measure.nli calls, because those carry only pair TEXTS and 7.2% of claim texts are emitted by more than one claim (measured on 40 panelA items), so agent identity is not recoverable. Any instance-preserving aligner must therefore reconstruct the pairing, duplicating target construction and the argmax/conflict loop. Guard that duplication with a test comparing BOTH the observations and the full measurement-call sequence against align_anchored on real cached data (tests/test_wct3_align.py), or the two copies will silently diverge.
